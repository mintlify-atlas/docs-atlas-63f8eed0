Anatomy does not draw diagrams. It invents a real, well-made physical object whose mechanism *is* the concept, then builds that object from dozens of small, precise, solid parts in an isometric camera with four-tone shading, correct painter's order, and calm eased motion under the pointer and keyboard. Every number the figure shows comes from the same small model that moves its parts. The output is source you own — a Node build script and the page it writes, or React/Next.js geometry modules and components — not a black box.

## The one idea that matters

The central design rule is: **the object is the explanation.** Instead of boxes, arrows, and labels, Anatomy finds a recognisable physical thing whose working maps one-to-one onto the concept. The reader understands the idea because they recognise the machine.

Here is how earlier figures mapped:

| Concept | Object |
|---|---|
| One shared GPU context serving many canvases | A gantry plotter — one print head visiting 16 wells |
| A cache key that skips work when nothing changed | A pin-tumbler lock — when every pin matches, the plug turns and nothing is redrawn |
| Seven render targets with different bytes per texel | A chest of seven drawers, each as deep as its bytes |
| A separable blur (49 × 49 taps vs 49 + 49) | A bed-of-nails stamp beside two combs on rails |
| A spring that presses and leans | A test rig with springs, a probe, and a dial gauge |
| A height profile | A profile gauge pressed against the edge |
| Light that depends on facing | A small photo studio — key and fill lamps around a turntable |

Two ways this fails, both seen in practice:

- **Too abstract.** Stacked plates, floating slabs, or labelled boxes don't read as anything.
- **Too flat and bland.** One big slab with a few lines on it has no volume, no parts, and nothing to discover.

The fix for both is the same: a recognisable machine, built from many small, precise, purposeful parts.

### SKILL.md

`SKILL.md` is what Claude reads when you invoke `/anatomy`. It contains the complete 10-step workflow (from sizing the request to verifying the result), the concept-to-object mapping approach, the craft rules in short form, and a table of every file in `kit/`. It also tells Claude which reference documents to open at each stage. Because it is a plain Markdown file in a standard Agent Skill folder, OpenCode and Codex load it the same way.

### kit/

The kit is the drawing library the figures are built from. It uses only Node's built-in modules — nothing to `npm install`.

| File | Purpose |
|---|---|
| `kit/iso-kit.ts` | The whole core: camera, solids, a parts library, an SVG string renderer, card and page builders, and `ISO_CSS`. Copy it into a TypeScript project. |
| `kit/iso-kit.mjs` | The same core compiled to plain ESM, for Node build scripts. Import it directly. |
| `kit/iso.css` | `ISO_CSS` written out as a standalone file. |
| `kit/lathe.mjs` | Round parts on any axis: `lathe`, `solidOf`, `disc`, `ringBand`, `sphereOf`, `bandsOf`, `rodOut`, and more. |
| `kit/tube.mjs` | Pipes and cables: `tubePieces` splits a route into depth-sortable chunks; `tubeSvg` draws one. |
| `kit/gl.mjs` | The WebGL layer for shaders inside the drawing: `GLSL_ISO`, `glCamera`, `glLayer`, and the JS envelopes `smooth`, `burst`, and `settle`. |
| `kit/turn.mjs`, `kit/turn-build.mjs`, `kit/turn-audit.mjs` | The optional 3D mode (beta): groups, live layers, convex parts with materials, and the orbit audit. |
| `kit/audit.mjs` | Proves the geometry: nothing passes through anything, every end sits on a mount, every overlap is drawn in depth order. |
| `kit/react/draw.tsx` | Server-safe React components: `Solid`, `Line`, `Wire`, `Dots`, `FaceText`, `IsoFigure`, `Plate`. |
| `kit/react/live.tsx` | `"use client"` hooks: `useReadout`, `useLoop`, `useEased`, `useInView`, `useStillness`, plus `spring` and `follow`. |

### scripts/

The scripts directory contains headless Chrome verification tools that Claude runs to check its own work. These are not part of the build — they run after, and Claude reads every PNG they produce.

| Script | Purpose |
|---|---|
| `scripts/capture.mjs` | Desktop and phone screenshots, close-ups, and console checks with WebGL on. |
| `scripts/drive.mjs` | Scripted sessions: move, click, key, slow motion, wait-until, eval, contact sheets that catch pops. |
| `scripts/lines.mjs` | The line-end check: every texture line must end on a stroke, a dot, or an outline. Exits 1 on any failure. |
| `scripts/inline-kit.mjs` | `kitScript()`, `glScript()`, and `turnScript()` return the kit as source to inline into a standalone page. |
| `scripts/turn-check.mjs` | 3D figures: fidelity, depth order, pixel pops, line ends at 24 angles, and frame timing. |

## A figure arrives as source you own

The result of an Anatomy session is not a generated image or a component you can't edit. It is a Node build script (or React modules) that imports from `kit/` and produces an HTML page. You can read every path, change every part, add a new mechanism, or adjust the model that drives the motion — because you have the source.
